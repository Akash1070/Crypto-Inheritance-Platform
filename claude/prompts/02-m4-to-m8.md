## M5 — Release path
```
/build-milestone M5

Deliver: heir claim (passkey step-up) -> challenge window -> owner cancel on any passkey login -> release via the isolated apps/release-signer.
release-signer requirements: < ~1,000 LOC, minimal deps, no inbound access except mTLS from API, no egress, KMS-protected key (fake KMS locally, interface for real KMS), independently verifies chain signatures, challenge age by its own clock, no later cancel/checkin/pause, fresh heir step-up, no prior RELEASE; decrypts S, re-encrypts to heir key, emits RELEASE event, zeroizes memory, logs every decrypt, fails closed.
Heir recovery UI + CLI path; continuity options A/B/C from docs/04 §6.5; heir 'before you touch funds' guidance.
Tests FIRST: every way to release early must fail (rogue API, replay, rollback, clock skew, race at the last second, double release). Run the red-team scenarios 2, 3, 5, 6 from docs/05 §6 as automated tests.
Run crypto-change-review and /security-review. STOP: this milestone must be human-reviewed line by line.
```
