# Security Policy (template — fill in before public release)

## Reporting a vulnerability
Please report privately. Do **not** open public issues for security problems.
- Email: security@<your-domain> (PGP/age key: <fingerprint/link>)
- Or use GitHub's private vulnerability reporting on this repository.

Include: affected component and version/commit, steps to reproduce, impact, and any proof of concept. Please do not access, modify or exfiltrate real user data; test only with your own accounts and fake data.

## What to expect
- Acknowledgement within 72 hours; triage within 7 days.
- Critical issues (any path to early release or plaintext recovery) targeted for a fix within 14 days.
- Credit in release notes if you wish. Bounty details: <link once live>.

## Scope
Web app, API, `release-signer`, CLI, `crypto-core`, infrastructure we operate, build and release pipeline.
Out of scope: social engineering of staff, physical attacks, volumetric DoS, findings requiring a compromised user device, self-hosted instances you do not own.

## Safe harbour
We will not pursue legal action against good-faith research that follows this policy. (Counsel to finalise wording.)

## Supported versions
Latest release and previous minor version.
